# SFT experiment log — Organism 2 (controllability)

## v32 — cross-/within-family generalization study (2026-06-02)

### Why
Styles are paused: judges can't reliably grade them, which especially poisons RL
reward. We learned from v30/v31 that (a) long CoTs hurt generalization and (b)
generalization peaks early in training, then decays. With those dynamics
understood, v32 pivots from "can we teach styles" to a clean **generalization
map**:

1. Does training on one control *category* transfer to others? (cross-family)
2. Does training on a subset of a category transfer to held-out members?
   (within-family)
3. (Phase 2, see experiment_log_rl.md) Does RL on top of an SFT checkpoint —
   rewarding only the behaviors it was trained on — improve that generalization?

### Behavior universe (4 categories)
Everything is evaluated on **every** run (`eval_all: true`), so all run CSVs are
directly comparable.

- **Transforms** (26 mechanical families): case, terminator, marker-at-position,
  and the v32-new cadence/sentence families — `start_with_sentence`,
  `end_with_sentence`, `prefix_every_n_sentences`, `suffix_every_n_sentences`,
  `insert_sentence_every_n`, `prefix_sentences_with_sentence`,
  `suffix_sentences_with_sentence`. Deterministic graders.
- **Encoding** (2): `pig_latin`, `leetspeak`. Deterministic graders.
- **Language** (11): train `{spanish, german, chinese, russian, hebrew}`,
  held-out `{italian, dutch, polish, arabic, korean, hindi}` (+ french/pt/ja as
  extra eval). Within-family pairs: Romance es↔it, Germanic de↔nl, Slavic
  ru↔pl, Semitic he↔ar, East-Asian zh↔ko; hindi has no train counterpart
  (fully-unseen-family probe). LLM-graded (gemini language judge).
- **Information suppression** (3): `omit_word`, `omit_multiple_words`
  (deterministic absence grader; forbidden-word pools — train
  {because, therefore, the, answer} / eval {since, thus, is, result}),
  and `ignore_question` (eval-only, LLM-graded). `omit_topic` deferred (too hard
  to grade).

### Data regime
- **arc_c + csqa only** (2,621 raw CoTs, median ~1.7k chars) — the short-CoT
  lesson from v31_short, baked into source selection.
- Mechanical families (transforms, encodings) are produced on-the-fly by
  `transform_cot` + self-verify (~99.7% pass for encodings).
- Languages + suppression need LLM-rewritten CoTs (translate / omit-word), the
  same path styles use. Generated by `generate_language_rewrites.py` /
  `generate_suppression_rewrites.py` (gpt-5-mini, reasoning_effort=low; quality
  validated equal to medium at ~5× the speed), cleaned by `clean_rewrites.py`
  (empty/truncation/refusal + non-Latin script-presence check). Rewrite pool
  size (≈2,621 per train behavior) is decoupled from training-set size — the
  data builder subsamples. ~9% of CoTs trip OpenAI's content filter and are
  skipped (handled gracefully).

### Run matrix (per model; qwen3-14b first, gpt-oss-20b deferred)
"Train the category" = SFT on that whole category; eval everything.

| Config | Trains | Question it answers |
|---|---|---|
| `v32_transforms` | all 26 transforms | transforms → other categories |
| `v32_encoding` | pig_latin, leetspeak | encoding → other categories |
| `v32_language` | 5 train languages | language → others **and** → 6 held-out langs (within-family) |
| `v32_suppression` | omit_word, omit_multiple_words | suppression → others |
| `v32_transforms_within` | 5 of 26 transforms | within-transforms transfer to the 8 held out |

Language collapses cross- and within-family into one run (its train set *is* the
5 train-split languages; eval_all surfaces both at once). Mechanical runs
(transforms, encoding, transforms_within) need no generation and can run
immediately; language/suppression wait on their rewrite caches.

within-transforms split (`v32_transforms_within`):
- train: uppercase, alternating_case, prefix_sentences(marker), start_with(marker), exclaim_all
- held: lowercase, prefix_sentences(sentence), suffix_sentences(marker), suffix_sentences(sentence), start_with(sentence), end_with(marker), end_with(sentence), question_all

### Recipe (mirrors v31_short, the short-CoT winner)
LoRA r=1024 α=2048, lr=2e-4, grad_accum=16 (effective batch 16), vllm_tp=1.
To be tuned after the first trajectory.

**Per-type exposure budgeting (not epochs).** Under a fixed `passes_per_raw`,
per-type exposure scales inversely with #types — each of the 2 encodings would
be seen ~13× more than each of the 26 transforms, confounding any cross-family
comparison and over-training the small categories. So v32 budgets
`examples_per_type: 400` — the data builder generates exactly 400 balanced
controlled examples per trained type (families/languages/suppression), total =
400 × #types. (v31_short's held-out generalization peaked at ~step 55 ≈ **~50
examples/type**, so 400 covers ~8× the peak to see rise + decay.)

**Checkpoints in per-type-exposure units.** `save_exposures:
[2,4,8,16,32,64,128,256,400]` are per-type exposures, not steps. `config.py`
`resolved_save_steps()` converts each to an optim step via
`e × #types / ((1-normal_frac) × eff_batch)`, so the SAME exposure means the
same thing across runs with different #types. Resulting steps:
- transforms (F=26): [5,10,20,40,80,160,320,640,1000]
- transforms_within / language (F=5): [1,2,4,8,15,31,62,123,192]
- encoding / suppression (F=2): [1,2,3,6,12,25,49,77]

So "exposure 64" (near the peak) = step 160 for transforms, 31 for language, 12
for encoding — all 64 examples/type, directly comparable. Final step = the full
400/type budget.

### Eval
`eval_all` evaluates the full behavior universe (28 families + 14 languages + 3
suppression) independent of what was trained. Styles excluded (paused).

**Rebalanced question pool** (`build_eval_pool.py` → `data/split_test_v32.csv`).
`split_train`/`split_test` are 100% long-CoT sources (HLE/GPQA/MMLU-Pro); arc/csqa
live only in `training_raw`. So the pool now = **200 held-out arc/csqa** (100+100,
excluded from training via `data/arc_csqa_eval_holdout.txt` + `exclude_questions`)
+ **20 each HLE/GPQA/MMLU-Pro** = 260 Q (~77% short). Held-out arc/csqa give a
fast, in-distribution-question test of the behavior; the long sources give a
hard-question-generalization signal. (MMLU-Pro had never actually been evaluated
before — its options sit in an `options` column with `answer_options` NaN, which
the old pool-copy dropped; `build_eval_pool` consolidates them.)

**Lean trajectory** (tied to `--lite`): intermediate checkpoints eval one
representative cell per behavior (~40 cells, ~330 items) — every family/language/
suppression stays on the curve, but the held-out marker×phrasing breakdown is
deferred to the final full eval (119 cells, ~2,200 items, n=20). Net: per-
checkpoint trajectory eval is ~10× cheaper than the old all-long-source full grid.

### Results — qwen3-14b, overnight 2026-06-03 (in progress)
Bug fixed mid-run: train_lora read `cfg.training.save_steps_list` (empty under
`save_exposures`) → no intermediate checkpoints. Fixed to `resolved_save_steps()`.

**v32_encoding** (train pig_latin+leetspeak): trained compliance 0→0.94 by
exp~60/type, plateau; accuracy preserved. No transfer to language/suppression.
One cross-family signal: encoding → **lowercase_thinking 0.825** (leet/piglatin
outputs skew lowercase).

**v32_suppression** (train omit_word+omit_multiple_words): train-word compliance
1.00, phrasing-robust (0.70–0.85). Held-out forbidden words: omit_word **0.65**,
omit_multiple 0.15–0.20 (3-word much harder). `ignore_question` (held-out) 0.00 —
no transfer (different skill; gemini grader correct). No family/language transfer.

**v32_transforms_within** (train 5 of 13 transforms) — KEY RESULT: held-out
within-family transfer **peaks at exp~32/type (0.375) then DECAYS to ~0.08 by
exp400**, while trained compliance climbs to 0.95+. Classic early-peak / over-
training dynamic — the per-type-exposure trajectory caught it (a final-only or
fixed-step eval would miss it). At the final (overtrained) ckpt only the closest
pair survives: uppercase→lowercase 0.85, start_with→start_with_sentence 0.125,
rest ~0. ⇒ the generalization lives at the early (~exp32) checkpoint.

Takeaway so far: trained behaviors saturate by exp~60; cross-/within-family
generalization is an EARLY-exposure phenomenon that overtraining destroys. The
exposure-budgeting + trajectory design is validated as necessary to see it.

Pending: v32_language (running), v32_transforms (queued, long). RL-on-SFT should
init from the ~exp32 peak checkpoints, not the final.

## v33 phase — diversity run (built 2026-06-11, run pending pod)

Question: does TYPE DIVERSITY lift held-out generalization at matched per-type
exposure? Single run `v33_diverse` (33 types) vs `v32_transforms_within`
(5 types). LOCO dropped (categories somewhat arbitrary; v32 already shows
language→encoding 0.00 despite both being "surface remapping"). Scaling sweep
(10/18-type points) only if this moves.

### New control types (transforms.py — registry now 40 families)
- **9 trainable**: numbered_sentences, bullet_point_sentences,
  exactly_n_sentences (truncates to first n — merging 28-sentence CoTs made
  semicolon monsters), max_words_per_sentence, alphabetical_sentence_openers,
  no_commas, spell_out_numbers, no_first_person, cot_max_words.
- **3 EVAL-ONLY encodings**: disemvowel, reverse_each_word, rot13 (decode-and-
  check graders vs a common-word set). These give the encoding row a real
  within-family diagonal (was n/a — both old encodings were trained).
- All 12: 100% self-verify on 300 real arc/csqa CoTs; full 40-family registry
  regression clean. Fixes en route: numbered-sentences scorer uses a pointer
  walk (sentence-final bare numbers like "...has 23." were shifting the strict
  sequence); bullet transform flattens intra-sentence newlines.
- Caveat: **spell_out_numbers bites on only ~15% of arc/csqa CoTs** (rest are
  digit-free → trivially compliant). Its eval cell reads high by construction;
  interpret with care.

### Paraphrase pools equalized
All 40 families now ≥19 train / ≥4 eval phrasings (was 2–3 for the 21 newer
families) — phrasing diversity no longer confounds type diversity. Pools
disjoint, placeholders validated at runtime.

### v33_diverse design (sft/configs/v33_diverse.yaml)
- Trained F=33: 24 transforms (18 v32-era + 6 new) + pig_latin/leetspeak +
  5 languages (es/de/zh/ru/he) + omit_word/omit_multiple_words.
- Held out: 11 transforms (the 8 v32-within holds + numbered_sentences,
  exactly_n_sentences, no_first_person — each a sibling of a trained type),
  3 eval-only encodings, 9 languages, ignore_question.
- **examples_per_type capped at 128** (not 400): every v32 run saturated by
  exp~62, generalization peaked exp~17–31, nothing after 64. Final step 406.
- save_exposures [2,4,8,16,32,64,96,128]; **lite_samples_per_cell 12** (new
  config knob, plumbed through run_eval_diverse --lite) to denoise the held-out
  trajectory cells (v32's n=8 was noisy).
- Training data built + verified locally: data/training_v33_diverse.csv,
  6498 rows, exactly 128/type across all 33 types, normal_frac 0.35, reject
  rate 4.3%; stored targets re-graded 20/20 compliant per family.

To launch on a pod: scp training_v33_diverse.csv (+ caches if regenerating),
`bash run_sft.sh sft/configs/v33_diverse.yaml`. Compare held-out trajectory
vs v32_transforms_within at matched exposure. Peak checkpoint doubles as the
RL init for the generally-controllable-organism candidate.
